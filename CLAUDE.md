# Project notes

Keep this section current: when you learn something non-obvious about this
codebase, add it here. `AGENTS.md` is regenerated by `next dev`, so put notes
here, not there.

## UI primitives (`src/components/ui`)

- One folder per primitive: `ui/<name>/<name>.tsx` plus an `index.ts` barrel.
  Import the folder: `import { Button } from "@/components/ui/button"`.
  `ui/index.ts` re-exports every folder with `export *`.
- The primitives are vendored from **Vinyaas**, the owner's own shadcn-style
  registry (`~/01-projects/01-active/vinyaas`, sources in
  `apps/docs/registry/new-york/ui/<name>/index.tsx`, published at
  https://vinyaas.vercel.app/r). Prefer a Vinyaas component over writing a new
  primitive.
- Don't run `vinyaas add`/`init` here. The CLI writes `ui/<name>/index.tsx`
  and imports `cn` from `@/lib/utils`. This repo uses `<name>/<name>.tsx` and
  `@/lib/cn`, and has no `components.json`. To add one, copy the registry
  source into `ui/<name>/<name>.tsx`, swap `@/lib/utils` for `@/lib/cn`, add
  `index.ts`, and add any sibling CSS (e.g. `tooltip.css`) or deps it declares.
- Each vendored file starts with a `// Source: Vinyaas registry …` comment
  that lists every local change. Keep that list accurate when editing. Current
  deviations:
  - Button: adds `gap-1.5` and default `[&_svg]` sizing (lucide icons are 24px
    otherwise; IconButton children rely on it).
  - Badge: adds `success` / `warning` / `info` variants (admin status badges).
  - Card: `CardTitle` is an `<h2>` instead of a `<div>` (heading outline, and a
    test asserts it).
- Project-only compositions (not from Vinyaas): `Link` (i18n-aware, external
  hrefs → `<a>`), `ButtonLink` (Link styled with `buttonVariants`; pins hover
  text color because Link variants add their own), `IconButton` (required
  `aria-label`; sizes map to Button's `icon-*` sizes).
- Button API is cva: variants `default | secondary | outline | ghost |
destructive | link`, sizes `default (h-9) | xs | sm | lg | icon | icon-xs |
icon-sm | icon-lg`. To style a non-button element as a button, use
  `buttonVariants({ variant, size })`. There is no `primary` variant and no
  `buttonClassName`/`buttonSizes` export any more.

## Theme (`src/app/globals.css`)

- Colors follow the Vinyaas/shadcn token contract: `:root` = light,
  `.dark` = dark, mapped to utilities in `@theme inline`. The root layout always
  puts `dark` on `<html>`, so only `.dark` values ship today.
- `@custom-variant dark` makes `dark:` follow the `.dark` class (Vinyaas
  components use `dark:` utilities).
- Radii derive from `--radius` (sm = −4px, md = −2px, lg = base, xl = +4px).
- Project extensions on top of the contract: `success` / `warning` / `info`
  (+ `-foreground`), `destructive-foreground`, and the layout/type tokens and
  custom utilities (`type-*`, `stack-*`, `surface-card`, `app-container`, …).
  Define new color tokens in both `:root` and `.dark`.
- Charts read `var(--chart-1..5)` directly (`src/components/charts/theme.ts`).

## Repo hygiene

- Many tracked Finder-style duplicates exist (`page 2.tsx`, `db/client 3.ts`,
  `tests/unit/* 2.ts`, …). They are compiled by `tsc` and picked up by Jest, so
  API changes have to keep them type-checking. Don't edit them as if they were
  the real file; ask before deleting them.

## Testing

- Don't force tests. Don't add per-component or per-feature tests by default.
- Write a test only for pure logic with real branching or risk: e.g. the
  stack-grading function, password and session verification.
- Don't block work on coverage. Keep existing tests passing; if a change breaks
  a test that only asserts markup, update or remove that assertion rather than
  adding new ones.

## Admin auth (password-only)

- No accounts. `/unlock` takes the password, checks it with bcrypt against
  `ADMIN_PASSWORD_HASH`, and sets a signed `pf_admin` cookie (HMAC over
  `AUTH_SECRET`, 8h, httpOnly, sameSite lax). `src/proxy.ts` checks the cookie
  for `/admin/*`; `hasAdminSession()` in `src/auth/admin-gate.ts` checks it in
  server code. Lock = `lockAdminAction`.
- `ADMIN_EMAIL` is no longer used to log in. It only seeds the owner identity
  id (`ownerIdentityId()`), so application rows created before the change keep
  their owner. Keep it unchanged.
- **`$` in `ADMIN_PASSWORD_HASH` must be escaped as `\$` in `.env`.** Next runs
  dotenv-expand over `.env` values, so an unescaped bcrypt hash loads as a
  corrupted string and the password can never match. The same expansion
  happens to values set in the shell (`process.env`), and an escaped value
  there is kept with the backslashes, so it doesn't work either. Put the hash
  in `.env` with escapes.
- Redirects that depend on the session must be in `src/proxy.ts`. A
  `redirect()` called from a streamed page (e.g. `/unlock` when already
  unlocked) is sent as a 200, not a 307.
- Browser-test the auth flow with Playwright, not hand-built server-action
  POSTs. The hand-built POST returns "Connection closed" and doesn't prove
  anything about the app.
