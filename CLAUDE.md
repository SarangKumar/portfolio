## Gotchas

- `src/components/site/site-chrome.tsx` + `terminal.tsx`: the navbar's command
  icon (lucide `SquareTerminal`) mounts/unmounts `<Terminal>`, so clicking it
  twice used to land on the **404 page**. Cause: the scroll effect was written
  expression-bodied, `useEffect(() => endRef.current?.scrollIntoView(...))`.
  `scrollIntoView()` now returns a Promise in Chrome, so that arrow handed the
  Promise to React as its cleanup; on unmount React called it and threw
  "destroy is not a function". There's no `error.tsx`, so Next's
  `NotFoundBoundary` caught it and rendered `not-found.tsx` — the crash looked
  like a routing bug, which is what makes it hard to find. Keep the effect
  **block-bodied** (`{ ...; }`) so it returns `undefined`. Same trap applies to
  any effect whose one-liner returns a value.

## No raw HTML injection

- `dangerouslySetInnerHTML` is banned by lint (`react/no-danger` in
  `eslint.config.mjs`); `public/**` is eslint-ignored. Two places used to need it:
  - The pre-paint theme script now lives at `public/theme.js`, loaded from
    `layout.tsx` as a **synchronous** `<script src="/theme.js" />` in `<head>`
    (one `@next/next/no-sync-scripts` disable comment — sync is the point, a
    deferred script would flash the wrong theme). `themeScript` is gone from
    `theme-toggle.tsx`.
  - `json-ld.tsx` passes the JSON as a **text child** of
    `<script type="application/ld+json">`. React does _not_ entity-escape text
    children of `<script>`/`<style>` (verified against the rendered HTML: the
    block parses as JSON, no `&quot;`), so this is safe; the `<` → `\u003c`
    replace stays as defence against `</script>` in data.
- `suppressHydrationWarning` on `<html>` in `layout.tsx` is load-bearing: the
  theme script toggles `.dark` on `documentElement` before hydration, so the
  class always differs from the server HTML. Don't add it anywhere else —
  extension-injected `<body>` attributes (Grammarly's
  `data-gr-ext-installed`) are a dev-only, extension-only warning, not a bug
  to paper over. The only no-suppress alternative is reading the theme from a
  cookie server-side, which makes the root layout dynamic.

## Theme

- `globals.css`: shadcn palette (orange primary, `--radius` 0.5rem, `--chart-1..5`)
  exactly as given — don't hand-pick new oklch values. `--glow`/`--logo-glow`/
  `--mesh-a/b/c` are `--primary` at different opacities, not new hues; project
  accent colors (project cards, resume stat strip) cycle through the given
  `--chart-1..5`, nothing invented. `success`/`warning`/`info` were dead
  (referenced in `@theme inline`, never defined) and have been removed —
  don't re-add them without also defining them from existing tokens.
- Use semantic utilities (`bg-primary`, `text-muted-foreground`).
- Motion: `fade-up`, `lift`, `glow-breathe`, `timeline-dot`; stagger via
  `style={{"--delay": ...}}`. All respect reduced motion.
- `src/components/site/timeline.tsx`: one continuous "lifeline" (not split
  rails, no `Marker`) through all of `/experience`, oldest first. The dot
  sits next to the title, centered via `items-center` on a flex row they're
  both in (`RAIL_X`/`INDENT` constants). **Don't** center the dot with
  `top: 50%` on an absolutely-positioned element inside a `height: auto`
  wrapper — that was the first two attempts here, and it's a real CSS trap:
  a percentage `top` on an absolute child only resolves against a parent
  with an explicit (non-auto) height; against an auto-height parent every
  browser falls back to the element's static position, so the dot rendered
  ~18px too high regardless of content length, verified with
  `getBoundingClientRect()` before the flexbox rewrite fixed it exactly
  (0px offset, checked programmatically, not just eyeballed). The line is a
  separate absolutely-positioned span at the same `RAIL_X`, so it passes
  through the dot's exact center. `PublicExperience.kind` ("work" |
  "education") picks the dot icon and shows as a small badge on the entry.
- `src/components/site/github-contributions.tsx`: fetches
  github-contributions-api.jogruber.de (6h revalidate, no token) for the
  GitHub handle in `contactProfile.socialLinks`, renders its own heatmap grid
  (no iframe/embed). Fails silently (renders nothing) if the API is down —
  it's a flourish, not load-bearing.
- `src/components/site/project-card.tsx`: per-project accent colour cycles
  through `--chart-1..5`; `featured` prop drives the bento lead card on Home.
- Typography: use `@/components/ui/typography` (`TypographyH1/P/Lead/
Blockquote/Muted`, etc.) for prose and page titles, not raw `<p>`/`<h1>`.
  `PageHeader` already does this — build new pages on it rather than
  hand-rolling headers.

## Admin panel

- `src/components/admin/`: `admin-app.tsx` (shell, nav, Firestore I/O),
  `schema.ts` (field lists), `fields.tsx` (field renderers), `admin-options.ts`
  (choice lists), `card-preview.tsx` (live preview).
- Multi-selects are data-driven: a `Field` gets `options: OptionSource` and the
  renderer pulls that list from `OptionsContext`, which `Dashboard` fills via
  `useAdminOptions(store, reload)` (reads every collection, all statuses, so
  drafts are selectable too; falls back to seed). `strict: true` = ids/slugs
  only, no free text. Values already saved stay selectable even once their
  source item is gone (`withCurrent`), so editing a doc can't silently drop a
  stale slug. Every `list` field now has an options source; `lines` fields
  (`highlights`, `currentFocus`, `achievements`) stay textareas — they're
  prose, not tags.
- Field types beyond the basics: `career` and `sections` replace raw JSON for
  `site.career` and `site.homeSections`; `icon` is the project icon picker.
  `sections` writes all six keys every time (off = `false`, never dropped), so
  the `SiteConfig["homeSections"]` shape stays complete.
- Project icons upload **without** a Storage bucket or new env: `fields.tsx`
  cover-crops to 128px and encodes WebP (falling back to PNG) on a canvas, then
  stores the data URL in `iconData` on the Firestore doc. Kept under
  ~60k chars against the 1 MiB doc cap, stepping quality/size down until it
  fits. `lib/content.ts` maps `iconData` → `icon` when serving, so the public
  components stay unaware. `ProjectIcon` must pass `unoptimized` for
  `data:` sources — the Next image optimizer can't fetch them.
- The live card preview renders the **real** public cards, so a draft looks
  exactly like the site. That's why `content-cards.tsx` exists: `PostRow`,
  `BookCard`, `BookmarkRow` were extracted out of the blog/library pages to be
  shared. Drafts are merged over `seed[name][0]` so missing fields can't crash
  it. It's a **fixed** height (`h-64 sm:h-72`), not `h-full` — `h-full`
  collapsed it, since the grid track has no resolved height to fill.
- The card preview is a **full-width row above the form**, never a side column,
  and that's load-bearing. The public cards size themselves with _viewport_
  breakpoints (`ProjectCard` is `sm:grid-cols-[3rem_1fr_auto]`), but a column
  in the editor's `xl:grid-cols-2` split is only ~396px wide: the sidebar
  (14rem) and gaps leave ~824px, halved, less `px-5`. On a wide screen every
  `sm:`/`lg:` rule still matched while the box was ~356px, so the card rendered
  its desktop layout crushed into half the width. Full-width makes the preview
  ~824px against the real page's 1088px — over the 640px `sm` threshold — and
  on a phone it's genuinely narrow, so the mobile layout is the correct one.
  Don't "fix" a cramped preview by shrinking the card; give it width, or the
  viewport breakpoints will keep lying. (A container query would be the other
  answer, but it means rewriting shared public components.)
- The "Preview" button only toggles the long-form markdown preview; the card
  preview is always live for collections in `HAS_CARD`.

## Token-saving

- Pipe long output through `tail -n 30`/`grep`. Never print registry JSON.
- Don't read the backup tarball or the aavedak repo unless needed.
- Checks: `npx tsc --noEmit`, `npm run lint`, `npx prettier --check .`.
- **npm, not pnpm.** `package-lock.json` is the committed lockfile. A pnpm
  install here breaks `npm run lint`: pnpm's isolated `node_modules` leaves
  `eslint-config-next` unable to resolve `next/dist/compiled/babel/eslint-parser`
  ("Cannot find module"), because it only reaches its own `next` copy. If
  `node_modules/.pnpm` exists, the tree needs a plain `npm install` to recover.
